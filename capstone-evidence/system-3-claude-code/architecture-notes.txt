Why deploy-check uses forked context + read-only tools:
- Fork: isolates megabytes of enumeration output (file lists, diff parsing, check traces) in the sub-agent; main session receives only the structured verdict summary. Without it, the main context is contaminated with throwaway discovery output. Skill cites Branching Reality pattern; notes skill-level `context: fork` vs session-level fork_session.
- Read-only: skill never modifies files/pushes/deploys; without the constraint a pre-deploy check could itself mutate the tree it is validating (blast radius: a mistaken write during a read-only audit).
